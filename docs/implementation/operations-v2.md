# Operations, provenance and supported scope

FR-49–58 use separate versioned PDAs and the existing Token-2022 instrument. The controlled snapshot engine remains available; the distributor is an additional explicitly approved payment rail. An approved Merkle root proves membership, not historical ownership or correctness of its input archive.

## Historical index and retained proofs

`scripts/lib/distribution.mjs` replays a complete, ordered, finalized journal from genesis through a declared record slot. It rejects sequence gaps, reordered/duplicate instructions, post-record input, unavailable banks, supply/registry mismatch and silently excluded nonzero holdings. Eligibility versions and transaction/evidence references are retained. The archive provider must sign the canonical payload hash with Ed25519; the expected provider public key is pinned in operator configuration, separately from the journal. This authenticates the provider's assertion of history/completeness/finality. It does not independently prove Solana consensus or replace review of that provider.

`npm run distribution:index -- journal.json parameters.json public/distributions` requires `parameters.archiveProvider` plus `distribution`, `paymentMint`, `face`, `rateBps`, `frequency`, `policyVersion` and holder-bound `destinations`. The journal schema is exercised by `scripts/post-mvp.test.mjs`: `version`, `source`, `instrument`, `mint`, `finality`, `completeFromGenesis`, ordered `events`, finalized `bank`, and `attestation {provider,hash,signature}`. Hash excludes `attestation`; signature is base64 Ed25519 over the 32-byte canonical hash. Provider keys belong in the archive service, never the browser/repository.

The CLI writes replay output and a content-addressed manifest directory with independently retrievable leaf/proof JSON files. Vite and the Next production app serve the same `public/distributions` directory. The `/claims` page accepts a public manifest URL, verifies its canonical content hash, domain, integer formula, ordering, proofs and obligation against the approved on-chain distributor, then requests the bound holder signature. Generated archives are ignored by Git: deployment must explicitly copy/host them.

Local recovery target: retain immutable manifests/proofs for the lifetime of the claim window and at least 365 days after expiry; retain the source journal, attestation and configuration alongside them. Keep two independent copies and perform content-hash recovery before approval. For the local filesystem, RPO is zero after successful writes and RTO is a process restart plus retrieval; no hosted availability SLA is claimed. Production approval requires evidence that every holder can retrieve proofs from public storage independently of the operator's browser. An unavailable archive blocks client verification/claim preparation rather than silently reconstructing current balances.

Claims require approval, sufficient funding, canonical distribution/index PDA, bound holder/mint/destination, valid proof and time strictly before the deadline. Reclaim requires the configured authority and Clock at/after deadline. Reclaim observes all remaining donations/dust, records claimed/reclaimed totals and closes the empty vault. Partial claim completion is never reported as full payment.

## Authority and terms

`Governance` configures four independent owner sets: administration, registry, approval and funding, each up to five members with a threshold. Configuration is permitted only before the instrument is sealed and before any snapshot/action. A System-owned PDA signer pays CPI rent; governance state remains program-owned. Every privileged intent stores the exact instruction and account metas on-chain, an expiring commitment, role approval bitmap and replay flag. The UI can reopen an intent URL and reconstruct it from chain after losing storage. A second member must approve when threshold exceeds one. Exact allowlisted Recorda instructions execute through CPI; arbitrary program/system instructions and legacy unversioned coupon creation are excluded.

Governed transfers cannot omit canonical eligibility accounts. Registry approval, expiry, freeze, group and jurisdiction are checked. Begin verifies the complete approved registry's eligibility before locking; capture uses the declared record timestamp. Policy changes during an active action are blocked. Historical captured rights stay immutable. Only public policy outcomes are stored; KYC documents/PII stay outside chain state.

Terms modification is a distinct administration intent. The governance term version/URI/hash and financial terms are copied into each new action. Historical legacy terms and finalized rights/receipts are not rewritten. Voting alone never changes terms. Existing deployed v1 Coupon accounts retain their exact layout/decoder; new schemas use new seeds. Legacy coupon period IDs cannot be inferred, and governed configuration is rejected on sealed historical instruments. Use newly issued instruments; any historical migration requires an explicit attested period and authority strategy before deployment.

## External proposals and audit

The external adapter validates a versioned, canonical action payload and durably deduplicates `(source,eventId)`. Identical retry returns the proposal; different payload/evidence conflicts. It produces the same domain-bound Borsh payload hash as the program. A Scheduled action can attach one operator-authorized source/event/evidence commitment. Attachment is not approval or execution. Evidence hashes bind documents; their authenticity still requires review of the external source/attestation. External feeds receive no settlement authority.

Audit history pages legacy/current actions by stable address cursor and RPC signatures by native `before` cursor. Exports contain decimal integer inputs, rights, outcomes, commitments and signatures without browser keys/storage. Pruned/erroring transaction bodies are explicitly unavailable. Trusted RPC account responses remain an operational trust boundary. Closed or reassigned historical destination accounts may prevent current account-level verification; retained transaction/archive evidence is needed for historical ownership.

## Measured envelope and code provenance

`npm run benchmark:distribution` measures authenticated synthetic archive replay/manifest generation for 1, 4, 100, 1,000 and 10,000 holders. One observed Node 24 run: 10,000 replay 733.608 ms, manifest 313.589 ms, manifest 11,098,439 bytes, proof 448 bytes. These are offline measurements, not chain throughput. Native acceptance exercises up to four registered holders per instrument. `scripts/measure-protocol.mjs` measures the recorded evidence transactions (some SPL helper/setup calls are not recorded), rather than claiming total workload costs. It records successful/failed transaction count, compute, fees and explicitly scoped live program-account rent in `target/benchmarks/protocol.json`. No 100,000-holder or production capacity claim is made; larger on-chain batches/intent limits require measurement before support.

The new action/governance/distributor/index/adapter code is written in this repository. No external engine source files were copied: upstream reference commits/files/licenses are therefore not incorporated dependencies. Architectural references in ARCHITECTURE remain reference material. Runtime versions and full transitive integrity pins are in Cargo.lock/package-lock.json: Anchor JS 0.32.1 (MIT OR Apache-2.0), Solana web3.js 1.99.0 (MIT), SPL Token 0.4.15 (Apache-2.0), React 19.3.0 (MIT), Next 16.4.0 (MIT), Playwright 1.63.0 (Apache-2.0). Preserve distributed package license/notice files; run `npm ls --all` and inspect lockfiles before dependency updates. Existing vendored bigint-buffer remains separately identified in vendor/; no upstream security/test-count claim substitutes for local acceptance.

Production Next setup follows [official client component documentation](https://nextjs.org/docs/app/api-reference/directives/use-client) and [lazy loading documentation](https://nextjs.org/docs/app/guides/lazy-loading). `next-app` isolates App Router from existing FSD `src/pages`; shared browser screens load client-side with public RPC/program configuration. Only public environment values enter its bundle.

Source implementation and local acceptance do not deploy the new ABI. The historical Devnet binary, remote CI, human Phantom replay of all three current actions and demo video remain separate release evidence gates.
